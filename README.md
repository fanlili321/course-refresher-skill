# course-refresher

历史课程／册子／电子书的**时效性与合规更新** skill，供 Claude Code 使用。这是一个私有仓库，是 `course-refresher` skill 的**源代码托管地**——本地生效路径是 `~/.agents/skills/course-refresher/`（`~/.claude/skills/course-refresher/` symlink 到这里）。

> ⚠️ **必须保持私有。** 仓库里含身份合规红线、投顾组合的内部运作规则（🔒标记）、飞书知识库的 space id 与文档 token。不要转公开、不要把 `assets/kb_index.json` 单独外发。

## 这个 skill 做什么

一份写于某个时点的旧稿，放一年就会烂掉：数据过期、市场状态说反、产品入口改版、主体身份变了、今年的新变化完全没提。这个 skill 把旧稿对着「内容素材库」（飞书知识库，3000+ 张钉大原话知识卡）逐条过一遍，产出**可逐条确认的更新清单**，确认后在**新建的副本**上批量改写并留下修订痕迹。

不负责从零写课程（走 `book-course-script`）、直播大纲（走 `outline-builder`）、PPT（走 `live-ppt-builder`）。

## 五步流程

1. **建档** —— 读原稿（只读），取 block ID，判定基准时点
2. **抽取时效性断言** —— 按九类维度逐节扫，抽成表
3. **对素材库取证** —— 每条断言检索卡片，结论只有三种：无需更新／建议更新／需人工核实
4. **出更新清单，停下来等确认** —— 此时**还没有新建任何文档**
5. **新建文档 → 批量改写（带修订痕迹）→ 回读校验**

## 九类检查维度

前七类抓"说错了"：时点数据、市场状态描述、产品与服务、政策与制度、图片与截图、观点口径、引用与外部事实。

- **第 8 类 身份与合规表述** ★优先级最高。主体身份变动会让旧稿里所有"谁做了什么"的句子失效，这是合规风险不是时效问题。自查口诀：把句子拎出来问"这是谁做的？谁说了算？谁承诺的？"——答不上来或答案是螺丝钉，就不合格。**关键陷阱：去掉主语不等于合规**，螺丝钉口吻下无主语句读者默认主语就是他。
- **第 9 类 本年度新变化**（说漏了）。对照 `references/whats-new.md` 过一遍，但**只补稿子已经涉及的主题**，没讲的不硬塞——硬塞会把册子定位撑坏，比漏掉更糟。

## 七条铁律

1. **原稿全程只读**，连标注都不写回原稿；确认后才 copy 出新文档
2. **不编辑素材库卡片**（飞书是本地事实源的镜像，改动会被同步覆盖），发现卡片过时走划词评论
3. **改动必须逐条确认，确认信号要明确** ——「全采纳」「除了 3、7」算数；「确认试下」「可以」不算数
4. **不臆造数字和日期**，查不到依据的标「需人工核实」
5. **不把时点快照当现状，也不把内部规则写进稿子**（见下）
6. **图片不自动替换**，只标"待重制"
7. **保住原文风**，只换该换的句子

## 两条踩过的坑（写进铁律的来源）

**坑一：把时点快照当现状。** 曾据一张 2026-05-23 直播卡片（当时大盘 3.6-3.7 星）写出"2026 年投顾组合长期关闭申购、读者一分钱买不进"，而实际 2026-08-05 主动优选已重新打开申购、发车恢复。**`含时点数据` 的卡片只证明"那一天是这样"**，判断现状要按日期取最新卡片 + 交叉验证（公众号增量通常比直播卡片新）。

**坑二：把内部规则写给读者。** 改正后又建议在册子里讲"4.1 星打开、3.9 星关闭"的开关机制——这也不对，那是内部判断依据。

**正确姿势：用规则去判断，用带日期的状态去表达。** 稿子里写"截至 2026 年 8 月，某某组合处于打开申购的状态"，并标注**发布前需复核当期状态**。

## 素材库检索要点（实测）

内容素材库 space `7656740046485064660`，四层结构：**类(A–G) → 主题(如 B2) → 知识节点 → 知识卡（编号如 B2-221）**。类和主题两层正文是空的，只是目录容器。

卡片固定格式，其中三个字段最有用：
- `时效性`：`强时效` > `含时点数据` > `长期方法论`，前两类才可能是新变化
- `版本演变`：直接写明"原 X（日期）已被 Y 取代（日期）"，最硬的证据
- `最新最全表述`：采信这一段，是钉大的现行说法

检索的坑：
- `drive +search --space-ids` 的**查询词必须短**（2–6 字核心名词），多词空格拼接经常返回 0 条
- 有些口语说法搜不到（实测 `钉大课堂`、`场内定投` 均 0 条），要换同义／上位词
- `total` 上限 200，不是真实总数
- `wiki +node-list` 输出前有一行 `Found N node(s)`，解析 JSON 前先 `sed -n '/^{/,$p'`
- 搜索连续打空时回退 `assets/kb_index.json` 离线匹配

## 修订痕迹怎么做

飞书 OpenAPI **没有**写入原生「建议模式 / track changes」的接口。用三层组合达到等效效果，默认三层都做：

1. **修订痕迹渲染** —— 旧文 `<del>` + 灰色，新文红色
2. **锚定批注** —— 每处改动挂一条，写明"改了什么 + 依据哪张卡 + 置信度"，用户可逐条「已解决」
3. **文末变更汇总表**

另外新文档的第一版保持与原文一致作为基线，飞书「历史版本」可逐版对比。

## 这是活文档

跟 `outline-builder` 一样，用的过程中学到的新规则、新踩的坑，都要写回对应文件并 push 回这个仓库。清单类内容（尤其 `whats-new.md`）会过期，每次做更新任务前先按文件里写的方法刷一遍。
