## 主路径：空间内全文搜索

```bash
lark-cli drive +search --query "估值表" --space-ids 7656740046485064660 --page-size 20 --as user
```

返回每条：`title_highlighted`（含卡片编号，如 `B2-221-估值表的使用说明与颜色含义`）、
`summary_highlighted`（命中片段，`<h>`/`<b>` 是高亮标签，展示前先剥掉）、`result_meta.token`（卡片 token）、`result_meta.url`。

**实测的坑（很重要）：**
- 查询词要**短**。`"定投发车文章 每周二"` → 0 条；`"投顾组合"` → 200 条。空格拼接多个词几乎必然打空。
- 一次只搜一个核心名词。要覆盖面就多搜几次，别把词堆在一个 query 里。
- 有些口语说法搜不到（实测 `钉大课堂`、`场内定投` 均 0 条），此时换同义/上位词：
  `场内定投` → `场内基金` / `ETF` / `券商`；`钉大课堂` → `今天几星` / `课程`。
- `total` 上限 200，不是真实总数，不要当统计用。
- `--query` 上限 30 个字符。

## 回退路径：目录索引

搜索连续打空时，用 `assets/kb_index.json` 离线匹配（结构 `{"_meta":…,"topics":{"B2 螺丝钉星级与牛熊信号":[{"t":node_token,"n":节点标题},…]}}`）。
知识节点的标题写得很长很具体，直接按关键词 grep 就能定位到主题/节点，然后：

```bash
lark-cli wiki +node-list --space-id 7656740046485064660 --parent-node-token <节点token> --as user 2>/dev/null | sed -n '/^{/,$p'
```

拿到该节点下的卡片列表（标题即 `A1-001 …` 形式），再 fetch 卡片正文。

> `wiki +node-list` 会先打印一行 `Found N node(s)`，直接 `json.load` 会炸，先 `sed -n '/^{/,$p'`。

## 读卡片

```bash
lark-cli docs +fetch --doc <卡片token> --doc-format markdown --as user
```

卡片固定格式：

```
# 标题
> 领域：B 市场认知与估值 ｜ 主题：B2 … ｜ 节点：… ｜ 时效性：含时点数据 ｜ 编号：B2-221
## 最新最全表述     ← 采信这一段，这是钉大的现行说法
## 论据数据         ← 可选
## 金句             ← 可选
## 版本演变         ← 可选，但对本 skill 最有价值：直接写明"原X（日期）已被Y取代（日期）"
## 出处             ← 公众号/直播/课程 + 日期
## 更新记录         ← 何时并入、来源
```

**`时效性` 字段是分诊信号：**
- `强时效` → 活动、优惠、临时安排，最容易失效。
- `含时点数据` → 旧稿里对应的说法**大概率已过期**，重点核对，优先看「版本演变」。
- `长期方法论` → 规则、机制、观点类，通常不用改数字，但要看表述口径有没有变。

### ⚠️ 最容易犯的错：把时点快照当现状

**`含时点数据` 的卡片记录的是"某一天的事实"，不是"现在的状态"。** 一张 5 月直播的卡片说"组合目前关闭申购"，只证明 5 月关着，不证明现在关着。

实例教训：曾据 F2-412（2026-05-23 直播，当时 3.6-3.7 星）写出"2026 年两个组合长期关闭申购"，而实际上 2026-08-05 主动优选已重新打开申购、发车恢复（F2-490）。结论直接写反。

**判断"当前状态"必须做三件事：**

1. **按日期取最新**：把命中的卡片按「出处」「更新记录」日期排序，只采信最新那张；日期差几个月的一律不能当现状。
2. **交叉验证**：至少两张不同来源的卡片指向同一结论才下判断（公众号增量的日期通常比直播卡片新）。
3. **分清"规则"和"状态"，两者用途完全不同**：
   - **规则**（如"4.1 星打开申购、3.9 星关闭"）→ `长期方法论`，可靠，但这是**内部运作机制，只用于自己判断，不写进对外稿件**。读者不需要知道阈值，写了反而变成对组合运作的解释。
   - **状态**（现在几星、现在开没开）→ 这才是稿子里该体现的，但**必须带日期**："截至 2026 年 8 月，主动优选、指数增强投顾组合处于打开申购状态。"

**所以写稿的正确姿势是：用规则去判断，用带日期的状态去表达。** 反过来做（把机制讲给读者、状态写成"目前"不带日期）两头都错。

在更新清单里，这类条目一律标注「**发布前需复核当期状态**」，因为从出清单到发布之间状态可能又变了。

**`版本演变` 是最强证据。** 例：
`原"第2946期估值表"（2026-08-04）已被"第2952期估值表"表述取代（2026-08-12）`
—— 旧稿写"2000多期"就可以直接给出建议新表述和依据。

## 检索节奏建议

一条待核对断言，按这个顺序，命中就停：
1. 断言里的**专有名词**搜一次（如 `月薪宝`、`红利低波`、`个人养老金`）
2. 没命中 → 换**上位概念**（如 `投顾组合`、`养老账户`）
3. 没命中 → grep `kb_index.json` 找主题 → `node-list` 列卡片
4. 还没有 → 标「库里无依据，需人工核实」，**不要自己编**

## 发现卡片本身过时了

不要改卡片正文（镜像会被覆盖）。选中问题句 → 划词评论，写清问题（例："这个规模数据是 2024 年的，建议更新"）。
系统每周自动汇总未解决评论给维护者。评论可用 `lark-cli drive` 的评论能力，或提示用户手动评。
